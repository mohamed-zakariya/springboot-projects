1. High-Level Overview

This project is a Spring Boot REST API that returns weather forecast data for a city. A client calls GET /api/weather/{city}, the app requests forecast data from the Visual Crossing Weather API, maps that response into simpler DTOs, returns JSON, and caches the result in Redis for 10 minutes.

ControllerReceives HTTP requests and delegates work.
ServiceCalls the external API and maps weather data.
DTOsShape incoming and outgoing JSON data.
RedisStores repeated weather results temporarily.

3. Important Classes

WeatherAppApplication

What: The application entry point. Why: Spring Boot needs a bootstrap class. How: SpringApplication.run(...) starts the Spring container and embedded server.

@SpringBootApplication enables auto-configuration and component scanning. @EnableCaching enables annotation-based caching, which makes @Cacheable work.

weatherController

What: REST controller for weather endpoints. Why: It exposes weather functionality through HTTP. How: The base path is /api/weather. The method getWeather(@PathVariable String city) handles GET /api/weather/{city}.

WeatherService

What: Main business service. Why: It keeps external API calls, mapping, temperature conversion, and caching away from the controller. How: It reads configuration with @Value, calls Visual Crossing with RestTemplate, maps the result into WeatherResponseDTO, and returns it.

RedisConfig

What: Redis cache configuration. Why: The app needs to define how cached values are stored and how long they live. How: It creates a RedisCacheManager with a 10-minute TTL and JSON value serialization.

CacheController and RedisCacheService

What: A small debugging path for viewing Redis keys. Why: It helps you see what cache entries exist. How: GET /cache/keys calls RedisCacheService.getAllKeys(), which uses RedisTemplate.keys("*").

5. Spring Boot Architecture

Controllers

What: Classes that handle HTTP requests. Why: They form the public API boundary. How here: weatherController handles weather routes and CacheController handles cache key inspection.

Services

What: Classes that contain business logic. Why: Controllers should stay small and delegate real work. How here: WeatherService owns weather fetching and mapping. RedisCacheService owns direct Redis access for key lookup.

DTOs

What: Simple objects used to transfer data. Why: They keep external API shape separate from your own API response shape. How here: WeatherApiResponse is the external shape; WeatherResponseDTO is your API response shape.

Dependency Injection and Beans

What: Spring provides objects to classes automatically. Why: It reduces manual setup and lets Spring manage lifecycles, proxies, and configuration. How here: @Service, @RestController, @Configuration, and @Bean all create Spring-managed objects.

Repositories

The repository package exists but is empty. There is no database access layer in the current application.

6. Request Trace: GET /api/weather/Alexandria

  1. The HTTP request enters Spring Boot's embedded web server.
  2. Spring MVC finds weatherController because it has @RequestMapping("/api/weather").
  3. Spring matches @GetMapping("/{city}").
  4. Spring extracts Alexandria from the URL and passes it as city.
  5. The controller calls weatherService.getWeather(city).
  6. Because getWeather has @Cacheable, Spring checks Redis first.
  7. The cache key is calculated as city.toLowerCase(), so Alexandria becomes alexandria.
  8. If Redis has the value, Spring returns it without running the method body.
  9. If Redis does not have the value, WeatherService.getWeather("Alexandria") runs.
  10. The service builds the Visual Crossing URL and calls it using RestTemplate.
  11. Jackson maps the external JSON into WeatherApiResponse.
  12. The service maps that object into WeatherResponseDTO.
  13. The response is cached in Redis for 10 minutes.
  14. Spring MVC serializes the DTO to JSON and returns it to the client.

7. External Weather API Mapping

The external API call is built from values in application.properties: 

String url = baseUrl + "/" + city + "?key=" + apiKEY;

Then the service calls: 

WeatherApiResponse weatherApiResponse =
    restTemplate.getForObject(url, WeatherApiResponse.class);

Spring uses Jackson to convert JSON fields into Java fields with matching names. The service then performs manual mapping:

External FieldInternal DTO Field
resolvedAddressWeatherResponseDTO.location
days[0].hours[].datetimeHourlyForecastDTO.time
days[0].hours[].tempHourlyForecastDTO.temp, converted to Celsius
days[0].hours[].conditionsHourlyForecastDTO.condition
days[].datetimeDailyForecastDTO.date
days[].tempmin/tempmax/tempDaily temperature fields, converted to Celsius
days[].conditionsDailyForecastDTO.condition

8. Redis Caching

Where Redis is configured

Redis host and port are in application.properties. Cache behavior is in RedisConfig. 

spring.data.redis.host=localhost
spring.data.redis.port=6379
spring.cache.type=redis

How Spring connects to Redis

Because the project includes spring-boot-starter-data-redis, Spring Boot auto-creates a RedisConnectionFactory from the Redis properties. RedisConfig uses that connection factory to create the cache manager and Redis template.

What @Cacheable does

@Cacheable wraps the method with caching behavior. Before the method body runs, Spring checks the cache. If a value exists, it returns the cached value. If not, the method runs and the result is stored. 

@Cacheable(value = "weather", key = "#city.toLowerCase()")

Cache key, hit, and miss

  • Cache name: weather
  • Method key: lowercase city name
  • For Alexandria: alexandria
  • Typical Redis key: weather::alexandria
  • Cache hit: Redis returns the cached DTO and the external API is not called.
  • Cache miss: The service calls Visual Crossing, maps the data, stores the result, and returns it.

11. Design and Architectural Patterns

  • Layered architecture: Controller -> Service -> External API/Redis.
  • DTO pattern: Separate objects for external API input shape and your API output shape.
  • Dependency Injection: Spring provides services and infrastructure objects.
  • Configuration pattern: Properties and configuration classes separate settings from logic.
  • Proxy-based caching: Spring wraps the service method and adds cache behavior around it.
  • Adapter / mapper style: The service adapts Visual Crossing's response into your own response model.
